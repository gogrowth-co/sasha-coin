The Wall
08 / 11

Withdrawal turned out to be technically impossible.

What the deployed contract can do

+
addLiquidity()
Liquidity delta hardcoded positive — uint128 cast, no negative path exists.
$
rescueToken()
Sweeps ERC20 sitting directly in the helper. Currently $0 in both tokens — the funds aren't there.

Why it can't be worked around

The LP position lives in the shared PoolManager, keyed to whichever address called modifyLiquidity — the helper contract itself. Only a call where msg.sender == that exact contract can decrease it. msg.sender cannot be spoofed by any other contract or EOA — that's a base EVM guarantee, not a missing feature. The helper is immutable, not a proxy, and its code simply has no decrease-liquidity path. The hook contract and PoolManager itself have no admin escape hatch either.

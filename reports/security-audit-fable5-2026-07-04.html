High severity

H-1Documented Base agent EOA is a phantom — and ships in CROO code

Doc §3's 0xba3BB320d35773ae…8601 has 0 transactions on Base and fails checksum. Real Clawlett EOA: 0xba3BB32Fa5cfA…6662 (15 txs) — same prefix, different tail. Actual LP-miner wallet: 0x21AF…A9A9 (22 txs, key = MANTLE_AGENT_PK; AGENT_PRIVATE_KEY exists nowhere). The phantom is hardcoded in croo/src/reputation-proof.ts:7 — Sasha's reputation proof publishes an empty wallet. Fix before CROO judging Jul 12.

H-2The "Gnosis Safe" at 0x7833…13b9 is not a Safe

On-chain it's an EIP-1167 minimal proxy → impl 0x819cd026…d54a; every Safe ABI call reverts (likely an AgentKeyFactoryV3 clone). All §5 claims — "Safe holds all funds", Zodiac Roles, no-transfer — are unverifiable as stated. Current exposure small (~0.0054 ETH).

H-3Stop-loss / HF-emergency / funding-kill closes auto-execute from cron

The gate only holds actions flagged killSwitch && confirmGated. The monitor emits stop-loss CLOSE_POSITION, emergency DELEVERAGE, and CLOSE_HEDGE with killSwitch:true only — the 30-min cron (--execute) runs them with no human gate. Also /etc/cron.d/sasha-hedge hardcodes HEDGE_LIVE_OK=1, so that gate is permanently open on the automated path. May be intended for stop-loss speed — but doc and code must agree.

Medium severity

M-1Oracle pusher never enforces signal freshness

push-signal-to-xlayer.js logs signal age but never rejects stale signals — a dead pipeline keeps re-pushing old data, refreshing updatedAt and defeating the oracle's 6h staleness fallback.

M-2Hedge orphan-short sweep only runs on an empty LP book

With a mixed book (one open LP + a leftover short from a closed LP in another coin) the stale short is never closed — naked directional exposure persists indefinitely.

M-3Hedge state written without checking order fill status

pos.hedgeSize = target is set even if the IoC order didn't fill — dashboard reports delta-neutral when it isn't. Self-corrects next 30-min cycle (mitigating).

M-4CROO provider has no delivery idempotency

A replayed OrderPaid event on WebSocket reconnect triggers a second deliverOrder(); relies entirely on server-side rejection. Risk area #10 confirmed open.

M-5LiquidityHelper ignores ERC-20 return values

No SafeERC20 — fine for USDC.e/WOKB, unsafe if reused with non-standard or fee-on-transfer tokens. Can't handle native-currency pools.

M-6No key rotation on any contract

Oracle agent, helper owner, hook oracle all immutable; hook is baked into the PoolKey forever. Compromised X Layer key = fee griefing (bounded 50–10000, max 1%) until full redeploy + new pool.

M-7SashaAgentLog has never been used

On-chain: tradeCount()==0, agentId()==0 (doc claims agent #100 + per-trade attestation). Attestations actually go to the ERC-8004 registry. Doc claim falsifiable in one RPC call.

M-8Pre-announce tweet still stranded on trade failure

Pre-flight funds check works, but a trade that fails after the tweet posts leaves the public announcement up with no position behind it (Telegram alert only).

Low severity

L-1..L-5Minor items
